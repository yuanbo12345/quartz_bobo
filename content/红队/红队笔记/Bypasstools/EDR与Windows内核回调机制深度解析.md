# EDR与Windows内核回调机制深度解析

本文档旨在系统性地介绍Windows内核回调机制，及其在现代EDR（端点检测与响应）解决方案中的核心作用，并深入探讨相关的攻防技术原理。

---

## 一、什么是内核回调 (Kernel Callbacks)？

**内核回调**是Windows操作系统内核（NTOSKRNL）提供的一套官方API机制。它允许具有内核权限的第三方驱动程序向系统“订阅”特定类型的关键事件。当这些事件发生时，内核会暂停其正常流程，并主动调用（“回调”）预先注册的第三方驱动函数，从而赋予这些驱动在事件发生瞬间的**可见性**和**干预能力**。

对于EDR而言，内核回调是其实现底层、高权限监控的基石。

---

## 二、回调函数如何运作：一个具体的例子

以监控**进程创建**的`PsSetCreateProcessNotifyRoutine`回调为例，其工作流程如下：

1.  **注册阶段 (Setup)**
    *   EDR的内核驱动 (`edr_driver.sys`) 加载后，调用`PsSetCreateProcessNotifyRoutine` API。
    *   它将一个指向自己内部函数（例如 `EdrProcessMonitorCallback`）的**函数指针**传递给内核。
    *   内核收到后，将这个函数指针存入一个内部的、私有的回调函数指针列表中。

2.  **触发与执行阶段 (Action)**
    *   用户或系统尝试创建一个新进程（例如，运行 `malware.exe`）。
    *   在内核完成进程核心结构的创建，但尚未执行任何代码之前，它会遍历上述的回调函数指针列表。
    *   内核会逐一调用列表中的每一个函数，并将新进程的详细信息（父进程ID、命令行、文件名等）作为参数传递。

3.  **分析与决策阶段 (Analysis)**
    *   执行流进入EDR的`EdrProcessMonitorCallback`函数。
    *   EDR的代码开始分析传入的数据，根据其内置规则和行为模型判断此行为的风险。
    *   **示例**：如果EDR发现是`WINWORD.EXE`启动了`powershell.exe`并带有混淆的命令行，它会将其识别为高风险的无文件攻击。
    *   EDR可以仅记录日志，或直接在返回给内核的结构体中设置一个标志，要求**阻止**该进程的创建。

4.  **返回与收尾 (Return)**
    *   EDR的函数执行完毕，控制权返回内核。
    *   内核根据EDR的返回值，决定是继续创建进程，还是中止操作。

## 三、EDR在内核中的“眼线”：主要的回调类型

EDR利用多种回调来构建其纵深防御体系，覆盖了操作系统的各个角落：

| 回调注册函数 (API)             | 监控的事件                                     | 对EDR的意义                                                  |
| ------------------------------ | ---------------------------------------------- | ------------------------------------------------------------ |
| `PsSetCreateProcessNotifyRoutine` | 进程的创建与退出                               | **核心**。监控恶意软件的执行、LOLBin的滥用、无文件攻击的启动。 |
| `PsSetCreateThreadNotifyRoutine` | 线程的创建与退出                               | 监控远程线程注入、代码注入等后渗透行为。                     |
| `PsSetLoadImageNotifyRoutine`    | 任何EXE或DLL被加载到内存中                     | 监控恶意DLL的加载、DLL劫持、内存中的恶意代码模块。             |
| `CmRegisterCallback`             | 注册表的创建、删除、修改、查询等操作           | 监控持久化技术（如Run键）、配置篡改、敏感信息窃取。          |
| `ObRegisterCallbacks`            | 进程/线程句柄的创建和复制                      | **强力保护**。用于阻止对`lsass.exe`等关键进程的内存读取和篡改。 |
| `FltRegisterFilter` (Minifilter) | 文件系统的所有I/O操作（读、写、创建、删除等） | 监控勒索软件加密行为、恶意文件的落地、关键系统文件的篡改。   |

## 四、规避内核回调的核心技术原理

攻击者为了“致盲”EDR，发展出了多种技术，其核心原理各不相同：

*   **用户层规避 (Bypassing User-Mode Hooks)**
    *   **直接系统调用 (Direct Syscalls)**：不通过`ntdll.dll`等被EDR挂钩（Hook）的中间层，直接使用`syscall`汇编指令进入内核，使EDR的用户层监控失效。
    *   **Unhooking**：从磁盘读取干净的`ntdll.dll`副本，用其覆盖内存中被EDR修改过的函数，从而“拆除”Hook。

*   **内核层规避 (Bypassing Kernel-Mode Callbacks)**
    *   **BYOVD (Bring Your Own Vulnerable Driver)**：这是目前最主流的内核级规避技术。其原理是利用一个**有合法签名但存在漏洞**的第三方驱动。攻击者在用户层利用该驱动的漏洞，获得在内核模式下任意读写内存的权限，从而可以：
        1.  **定位**：通过扫描内核内存，找到存储回调函数指针的内部数组。
        2.  **识别**：遍历数组，通过函数地址判断哪个回调属于EDR的驱动。
        3.  **移除**：将EDR的回调函数指针从数组中清零或移除，使其失效。

## 五、常见误区与深度解析 (Q&A)

**Q: 木马不上线后，执行`whoami`等简单命令会立刻被报毒吗？**
**A:** 通常不会。高级EDR基于**风险评分和行为链分析**。单个良性命令（即使被回调捕获）风险分很低。只有当一系列行为（如：进程注入 -> 执行命令 -> 修改注册表）串联起来，累计风险分超过阈值时，才会触发警报。不移除回调，等于是在一个布满探头的环境中进行高风险操作，极易被捕获。

**Q: 任何敏感行为都会被内核回调立刻检测到吗？**
**A:** 回调会**捕获**到行为，但**不一定立刻报毒**。回调是**数据收集器**，而决策由**分析引擎**（用户层服务+云端）做出。回调提供了“发生了什么”的原始数据，而分析引擎结合上下文判断“这是否是恶意的”。攻击者可以通过伪装行为（如注入到正常进程）来尝试欺骗分析引擎。

**Q: 为什么说转储凭证等操作需要BYOVD？**
**A:** 因为保护`lsass.exe`等关键进程的`ObRegisterCallbacks`是一种极其强力的内核级保护，它直接在对象管理器层面阻止了进程句柄的获取。任何用户层的绕过技术都无法对抗它。因此，必须使用BYOVD进入内核，从根源上（内核层）解除或绕过这种保护。

## 六、总结：攻防的博弈

内核回调是现代操作系统安全体系的重要一环，也是EDR实现深度监控的根基。理解其工作原理，是理解高级端点攻防对抗的钥匙。攻击方通过各种技术尝试让回调“失明”或“被欺骗”，而防守方则不断加强回调的覆盖面，并优化其分析引擎，以检测更隐蔽的威胁。这场在操作系统最深处的博弈，将持续不断地演进。
